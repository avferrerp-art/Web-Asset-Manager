════════ POR QUÉ ESTA TAREA ════════

Vamos a integrar los traslados internos entre almacenes (hoy la app solo maneja
despachos a clientes). Un traslado se define por el par origen→destino, así que
primero necesitamos los almacenes como entidad real.

Hoy el almacén es texto libre derivado del prefijo de location_id de Odoo
(`deliveries.almacenCodigo`, `sales.almacenOrigen`). Esta tarea NO cambia eso —
solo agrega la tabla nueva.

════════ TAREA ════════

1. Nuevo schema `lib/db/src/schema/almacenes.ts` (Drizzle), tabla `almacenes`:
   - id serial PK
   - codigo text NOT NULL UNIQUE      -- código corto para la UI
   - odooPrefix text NOT NULL UNIQUE  -- prefijo EXACTO de location_id en Odoo
   - nombre text NOT NULL
   - plaza text NOT NULL              -- 'Caracas' | 'Lecheria'
   - direccion text
   - latitud real
   - longitud real
   - activo boolean NOT NULL DEFAULT true
   - createdAt timestamptz NOT NULL DEFAULT now()
   Exportarlo desde `lib/db/src/schema/index.ts`.

2. Migración `lib/db/src/migrations/0006_almacenes.ts`, SQL idempotente
   (CREATE TABLE IF NOT EXISTS), registrada en `lib/db/src/migrations/index.ts`.
   (Las migraciones existentes van de 0000 a 0005 — esta es la 0006.)
   Incluir el seed de las 4 filas con ON CONFLICT (codigo) DO NOTHING:

     codigo | odooPrefix | nombre           | plaza
     URB    | Urbin      | Urbina           | Caracas
     CCS    | CCS        | Caracas          | Caracas
     LEC    | LEC        | Lecheria         | Lecheria
     NVBLA  | NVBLA      | Nueva Barcelona  | Lecheria

   OJO: el odooPrefix de Urbina es "Urbin", NO "URB". Es el prefijo literal que
   Odoo usa en location_id ("Urbin/Existencias"). No lo normalices ni lo
   "corrijas". Las cuatro ubicaciones en Odoo son: Urbin/Existencias,
   CCS/Existencias, LEC/Existencias, NVBLA/Existencias.

3. Helper `resolveAlmacenPorLocation(location: string)` en el api-server:
   recibe el string completo de Odoo ("Urbin/Existencias") y devuelve el
   almacén cuyo `odooPrefix` coincide con el segmento anterior al primer "/".
   Devuelve null si no hay match — no inventes ni crees filas al vuelo.

4. Endpoint `GET /almacenes` que lista los almacenes activos:
   - Definirlo PRIMERO en lib/api-spec/openapi.yaml
   - Correr `pnpm --filter @workspace/api-spec run codegen`
   - Router nuevo src/routes/almacenes.ts, montado en src/routes/index.ts
     DESPUÉS de requireAuth
