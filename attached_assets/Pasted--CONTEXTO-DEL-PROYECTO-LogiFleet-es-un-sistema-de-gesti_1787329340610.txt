════════ CONTEXTO DEL PROYECTO ════════

LogiFleet es un sistema de gestión logística de flota. Importa ventas y
traslados internos desde Odoo, planifica despachos, calcula costos, y tiene una
app móvil para choferes.

Monorepo pnpm workspaces, Node 24, TypeScript 5.9. Estructura relevante aquí:

  lib/api-spec/         openapi.yaml — contrato de la API + config de Orval
  lib/api-zod/          GENERADO — NO editar
  lib/api-client-react/ GENERADO (hooks React Query) — NO editar
  lib/db/               Drizzle schema + migraciones
  artifacts/api-server/ API Express 5 (routers en src/routes/)
  artifacts/logistics/  Web React + Vite + wouter + shadcn/ui + React Query

Lee `replit.md` y `.agents/memory/`. Relevantes acá:
  - .agents/memory/hook-call-convention.md   (hooks generados: useHook({ query: {...} }))
  - .agents/memory/cache-bust-pattern.md
  - .agents/memory/visual-verify-behind-auth.md

REGLAS DEL REPO — no negociables:

════════ TAREA ════════

Exponer los traslados en la API y crear el módulo Traslados en la web.
SOLO LECTURA — sin planificación, sin asignar camión, sin crear ni editar.

1. En lib/api-spec/openapi.yaml (primero el contrato, después el codegen):

   GET /traslados
     query params: almacenOrigenId, almacenDestinoId, estadoLogistico,
     estadoOdoo, search
     respuesta por fila:
       id, referencia (deliveries.nombre),
       almacenOrigen {id, codigo, nombre, plaza},
       almacenDestino {id, codigo, nombre, plaza},
       cruzaPlaza (bool, true si almacenOrigen.plaza !== almacenDestino.plaza),
       mismoAlmacen (bool, true si almacenOrigenId === almacenDestinoId),
       fechaProgramada, fechaEfectiva, estadoOdoo, estadoLogistico,
       cantidadLineas, pesoCalculadoKg, volumenCalculadoM3

   GET /traslados/{id}
     lo anterior + líneas: productoId, codigo, descripcion, demanda, cantidad,
     unidad, diferencia (demanda - cantidad)

   Después: `pnpm --filter @workspace/api-spec run codegen`

2. Router src/routes/traslados.ts, montado en src/routes/index.ts DESPUÉS de
   requireAuth. Ordenar por fechaProgramada descendente, nulls al final.

3. Página artifacts/logistics/src/pages/traslados.tsx + ruta `/traslados` en
   App.tsx (agrégala después de `/ventas`, junto a los demás <Route> con
   ProtectedPage) + entrada en el sidebar en
   artifacts/logistics/src/components/layout.tsx (el array `navItems`, después
   de "Ventas"; usa el ícono ArrowLeftRight de lucide-react — ya se usa ese
   patrón de íconos en el resto del array, revísalo antes de importar uno
   nuevo).

   CLAVE DE UX: un traslado es "una venta sin cliente". Reusa los patrones de
   src/pages/ventas.tsx (tabla, badges, barra de búsqueda con
   src/lib/search.ts — usa matchesSearch, es accent-insensitive, así que
   "lecheria" sin tilde encuentra "Lechería") y de
   src/components/sale-detail-sheet.tsx para el panel de detalle. No inventes
   un lenguaje visual nuevo.

   Columnas de la tabla: Referencia · Origen → Destino · Fecha programada ·
   Estado · Artículos · Peso

   - Origen → Destino: SIEMPRE el nombre del almacén, nunca el prefijo de
     Odoo. "Urbina → Lechería", jamás "Urbin → LEC". Cuando cruzaPlaza es
     true, usa un badge o acento visual distinto — es el viaje que necesita
     camión grande y peajes; distínguelo del viaje urbano corto de un
     vistazo, sin que el usuario tenga que abrir el detalle.
   - Estado: una sola columna que combine estadoOdoo y estadoLogistico de
     forma legible (ej. "Confirmado en Odoo", "Por planificar",
     "Cancelado") — no dos badges compitiendo por espacio.
   - Filas con mismoAlmacen = true: atenuadas (opacity reducida), con
     tooltip "reubicación dentro del mismo almacén, no requiere transporte".
     Vas a tener pocas pero existen (Urbin/INT/00014 es un caso real).
   - Peso: si pesoCalculadoKg es null, mostrar "sin dato en Odoo" en el
     mismo estilo (itálica, gris tenue) que ya usa articulos.tsx. Con 40%
     de cobertura, ESTA es la vista más común de la columna — que se vea
     bien, no como un error.
   - Filtros por almacén de origen, almacén de destino y estado. En el
     selector de almacén usa el nombre completo con tilde (Lechería), no el
     código.

4. Panel de detalle: sigue el patrón exacto de la pestaña "Entregas" de
   sale-detail-sheet.tsx — es prácticamente la misma tarjeta:

     [Referencia]  [badge estado]
     Almacén de origen     Nombre completo (no el string crudo de Odoo)
     Almacén de destino    Nombre completo
     Fecha programada
     Fecha efectiva
     ┌─────────────────────────┬─────────┬───────────┬────────┐
     │ Producto                │ Demanda │ Entregado │ Unidad │

   En las líneas, resalta visualmente cuando demanda ≠ cantidad — es el
   faltante detectado en la recepción y hoy no se ve en ningún lado de la
   app. Usa un tratamiento sutil (color de texto o un ícono), no un badge
   rojo agresivo por cada línea: en ventas ya viste que hay volumen de datos
   y no todo desajuste es grave.

5. Si pesoCalculadoKg o volumenCalculadoM3 tienen valor, muéstralos en el
   encabezado del panel junto a las fechas. Si ambos son null, no dejes un
   hueco en blanco — usa el mismo "sin dato en Odoo" del resto de la app.
