════════ CONTEXTO DEL PROYECTO ════════

LogiFleet es un sistema de gestión logística de flota. Importa ventas desde Odoo,
planifica despachos (vehículo + chofer + ruta), calcula costos, y tiene una app
móvil para choferes.

Monorepo pnpm workspaces, Node 24, TypeScript 5.9. Estructura:

  lib/api-spec/         openapi.yaml — contrato de la API + config de Orval
  lib/api-zod/          GENERADO — NO editar
  lib/api-client-react/ GENERADO (hooks React Query) — NO editar
  artifacts/api-server/ API Express 5
  artifacts/logistics/  Web React + Vite + wouter + shadcn/ui + React Query
  artifacts/mockup-sandbox/  canvas de mockups (solo diseño, no producción)

Lee `replit.md` en la raíz y `.agents/memory/`. Para esta tarea son críticos:
  - .agents/memory/measurement-domain-semantics.md  (ventas y traslados NO
    comparten el mismo predicado de "sin dato" — ver más abajo, es el error
    más fácil de cometer en esta tarea)
  - .agents/memory/visual-verify-behind-auth.md
  - .agents/memory/hook-call-convention.md (si existe)
  - .agents/memory/cache-bust-pattern.md (si existe)

════════ LA TRAMPA: dos semánticas de "sin dato" ════════

`sinDatoCarga`/`formatCarga` (`src/lib/carga.ts`, usado por ventas) trata
CUALQUIER valor `<= 0` como "sin dato" — es una convención defensiva para el
cálculo de capacidad de ventas.

`trasladoSinMedida`/`formatTrasladoMedida` (`src/lib/traslado-medidas.ts`)
trata SOLO `== null` como "sin dato" — es el contrato real de lectura de
traslados.

Para todo lo que construyas en esta tarea sobre datos de traslado (peso
efectivo, volumen, el input de estimado), usa `trasladoSinMedida` /
`formatTrasladoMedida`. Para todo lo que sigue siendo de venta dentro del
mismo componente (porque `CargoWizard` ahora sirve a los dos), sigue usando
`sinDatoCarga`/`formatCarga` exactamente como hoy. No mezcles ni "unifiques"
ambos helpers — son semánticas de negocio distintas, no un descuido a
corregir.
